## Owner decision still open

**How should the execute bit persist over `/mnt/c` in VM mode?** The rig ruled
out `modefromsid`: `chmod` rewrote Windows DACLs and the mode did not survive a
remount. The documented alternatives are:

- `paguro allow`/file-manager action writes `$LXMOD` as an SMB extended
  attribute; ordinary `chmod +x` would not persist in this mode;
- a thin FUSE layer translates `chmod` to the extended-attribute operation;
- a Windows service component serves mode metadata itself.

The tradeoff is ordinary `chmod` compatibility versus another filesystem/service
component. If ordinary `chmod` is required, investigate the thin FUSE option
first; if the dedicated Allow action is acceptable, test the simpler EA route.
This is a product choice for the Paguro chat, not a blocker for Kayfabe recovery.
